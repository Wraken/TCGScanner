# Collection Sync through Google Drive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The desktop app keeps the user's collection in sync with their other devices through a `TCGScanner` folder in their Google Drive, with no server: one append-only journal per device, merged by every device.

**Architecture:** Every row change appends an event (JSON Lines) to a `sync_events` table in the same transaction; the Drive file `journal-<device id>.jsonl` is rendered from it and uploaded whole. Other devices' journals are downloaded and folded into the local rows by uid with last-writer-wins and final removals. A small REST client talks to Drive, `golang.org/x/oauth2` handles the installed-app sign-in with a loopback redirect, and a `syncer` runs one cycle at a time on start, focus, after changes (debounced) and on demand. A Settings screen shows the state.

**Tech Stack:** Go 1.26 (Wails v2 app at the repo root, `modernc.org/sqlite`), `github.com/google/uuid` (already an indirect dependency), `golang.org/x/oauth2` (new), `net/http` for Drive, `httptest` for every network test; React + TypeScript + Vite frontend in `frontend/` (`npm run build` = `tsc && vite build`), Wails bindings regenerated by `wails generate module` (`frontend/wailsjs` is git-ignored).

**Spec:** `docs/superpowers/specs/2026-10-19-collection-sync-google-drive-design.md`

## Global Constraints

- One file per device, `journal-<device id>.jsonl`, in a Drive folder named `TCGScanner`; a device never writes another device's file.
- Journal line format: UTF-8 JSON objects, `\n` separated; line 1 is `{"v":1,"op":"device","device","name","app","at"}`; every later line has `"v":1`, `seq` (per device, from 1, +1 each), `at` (RFC 3339, UTC, millisecond precision, e.g. `2026-10-19T14:02:11.120Z`) and one of the eight ops: `collection.create`, `collection.rename`, `collection.delete`, `copy.add`, `copy.update`, `copy.remove`, `price_ref.set`, `price_ref.clear`, with exactly the fields the spec's table lists. Readers ignore unknown fields and unknown ops and skip malformed lines with a log.
- Merge rules: per entity (collection `uid`, copy `uid`, price ref `card_id`); seq order within a journal; later `at` wins across journals, ties to the higher device id; a removal is final (tombstone); `copy.add` for a known uid is ignored; `game` is re-resolved locally from `card_id`, the event's value is the fallback.
- Events are recorded from the migration on, connected or not; the migration writes the bootstrap events once. Applying a foreign journal never emits events.
- Google: scopes `https://www.googleapis.com/auth/drive.file`, `openid`, `email`; installed-app flow with a loopback redirect on `127.0.0.1` and PKCE; the refresh token lives in `settings` (`sync_google_token`).
- Sync triggers: app start, window focus, a local change (debounced), "Sync now", a retry timer while the last cycle failed. One cycle at a time; never on the UI or scan path.
- First connection: no remote journal → push; remote journals and no local copies → pull then push; remote journals and local copies → the merge question before anything is applied or uploaded; "Not now" disconnects. No "replace" option.
- Settings screen strings (English): "Keep this collection in sync with your other devices through a `TCGScanner` folder in your Google Drive. Only that folder is accessible to the app.", button "Connect Google Drive", "Connected as <email>", status "Up to date · HH:MM" / "Syncing…" / "Offline, will retry" / "Sync failed: <reason>" / "Disconnected, sign in again", buttons "Sync now", "Disconnect"; merge dialog "Your Drive already holds a collection: N copies from <devices>. This PC has M copies. Merge both into one collection? Nothing is removed; copies present on both sides are kept as separate copies.", buttons "Merge" / "Not now".
- UI strings are English; styling uses the Nocturne tokens and the existing `n-*` classes, no new UI kit.
- Line endings: the repo stores LF; some working-tree files are CRLF (`core.autocrlf`). Edit files in place; never convert them.
- `go vet ./...` at the root has five pre-existing `unsafe.Pointer` warnings in `pkg/ort` and `pkg/tflite`; the gate is `go build ./... && go test ./...`.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A `copy.add` whose `collection` uid is unknown locally (the other device's journal has not been seen, or the collection was deleted): the copy must still appear, unfiled, never dropped. Test in Task 4.
2. Two devices create a custom collection with the same name: both exist as two collections; nothing merges by name. Test in Task 4.
3. A journal line longer than 64 KB (a long label or a future field) must decode; `bufio.Scanner`'s default limit would silently stop the journal. Test in Task 1.
4. A malformed line or an unparsable `at` in the middle of a journal: that line is skipped and logged, every other line still applies. Tests in Tasks 1 and 4.
5. The user deletes the `TCGScanner` folder from Drive while connected: the cached folder id is stale (404); the next cycle re-finds or re-creates the folder instead of failing forever. Test in Task 7.

  ```go
  const syncFormatVersion = 1
  const syncFolderName = "TCGScanner"
  // Ops.
  const (
      opDevice = "device"; opCollectionCreate = "collection.create"; opCollectionRename = "collection.rename"; opCollectionDelete = "collection.delete"
      opCopyAdd = "copy.add"; opCopyUpdate = "copy.update"; opCopyRemove = "copy.remove"; opPriceRefSet = "price_ref.set"; opPriceRefClear = "price_ref.clear"
  )
  // syncEvent is one journal line. Pointer fields serialise their zero value
  // ("foil": false, "collection": "") only on the ops that carry them.
  type syncEvent struct {
      V int `json:"v"`; Op string `json:"op"`; Seq int64 `json:"seq,omitempty"`; At string `json:"at"`
      Device, Name, App string                      // json "device", "name", "app" — omitempty
      UID, CardID, Game, Lang, ScannedAt, Model string // omitempty
      Foil *bool `json:"foil,omitempty"`; Collection *string `json:"collection,omitempty"`
      Product, NonEnglish int `json:"product,omitempty"`/`"non_english,omitempty"`; Label string `json:"label,omitempty"`
  }
  func encodeEvent(e syncEvent) ([]byte, error)          // one line, no trailing newline, V forced to 1
  func decodeJournal(r io.Reader) (device syncEvent, events []syncEvent, skipped int, err error)
  func syncJournalName(deviceID string) string           // "journal-<id>.jsonl"
  func syncJournalDevice(name string) (string, bool)     // inverse; false for other names
  func syncNow() string                                   // time.Now().UTC() as "2006-01-02T15:04:05.000Z"
  func formatSyncAt(t time.Time) string; func parseSyncAt(s string) (time.Time, error)
  func boolPtr(b bool) *bool; func strPtr(s string) *string
  ```

- [ ] **Step 3: Implement the migration in `sync_store.go` and call it from `migrate`**

`migrateSync` runs in one transaction: the `ALTER`s (errors ignored like the existing ones), the indexes and tables, `UPDATE … SET uid = ? WHERE uid = ''` row by row with `newUID()`, the device settings (`sync_device_name` = `os.Hostname()`, "this device" when it fails), then, when `sync_bootstrapped` is absent: the bootstrap events in this order — every custom collection (`ORDER BY created_at, id`) as `collection.create`, every card (`ORDER BY scanned_at, id`) as `copy.add`, every price ref (`ORDER BY chosen_at, card_id`) as `price_ref.set` — then `sync_bootstrapped = 1`. Collections before copies, whatever the dates, so a copy's collection exists when a reader applies the journal in `seq` order (this refines the spec's "chronological order": it is chronological within each kind). `at` and `scanned_at` convert SQLite's `YYYY-MM-DD HH:MM:SS` (UTC) to the journal format; `price_refs.chosen_at` is already RFC 3339. Rows also get `sync_at` = that `at` and `sync_by` = this device's id.

`renderJournal` writes the device line (`at` = now) then each `sync_events` row re-encoded with `Seq` = its `seq`.

- [ ] **Step 3: Implement `applySyncEvents` and the uid-keyed row functions in `sync_store.go`**

Sort the batch by (`at`, `Device`): the event's parsed time, then the device id string. In one transaction, per event:
- a `uid` present in `sync_tombstones` ignores every op (removals are final);
- `copy.add` of a known uid is ignored;
- every other op applies only when the event's key `(at, Device)` is greater than the row's `(sync_at, sync_by)`, compared as two strings in that order (`at` is a fixed-width format, so string order is time order); the row then takes the event's key. - `game` = `resolveGame(cardID)`, the event's `Game` when that returns `""`; an unknown `collection` uid stores NULL (unfiled);
- an unparsable `at` skips the event with a log.

`applied` counts the events that wrote a row. `applied_seq` per device = the highest `Seq` seen in the batch, upserted into `sync_sources` even when nothing changed.
